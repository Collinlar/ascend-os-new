# Ascend execution backlog

Read with [BUILD_PLAN.md](BUILD_PLAN.md), [DECISIONS.md](DECISIONS.md) and [SOURCE_REGISTER.md](SOURCE_REGISTER.md). This is an ordered delivery backlog, not a claim that every requirement in a referenced source belongs to the first release. Split each item into tickets with exact source IDs before coding. Owners are roles, not assumed available staff.

Priority: **P0** shared correctness/release blocker; **P1** required for the stated pilot/commercial release; **P2** later depth. Dependencies indicate delivery order; design and test preparation may start earlier. Every item also requires the common definition of done in the build plan.

## Tracking policy

Do not bulk-mark requirements complete because a backlog item has shipped. For each ticket, select requirements from `requirements.json`, record any decision override, attach implementation evidence and acceptance evidence, and set one of: not assessed, existing-unverified, gap, in progress, verified, explicitly deferred, or superseded by approved decision. Maintain a release coverage report showing unresolved Must/MVP requirements relevant to the advertised cohort.

Release acceptance is owned by product and operations as well as engineering. Approving a technical test is not approval of pricing, a vendor, legal terms, a refund policy or a promised hardware support level.
